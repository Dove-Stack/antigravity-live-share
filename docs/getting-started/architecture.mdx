Antigravity Live Share is a three-piece system: an **extension** that lives in
the IDE, a **signaling server** that relays events, and a **plugin manifest**
that registers the integration with Antigravity.

Every runtime message is a JSON envelope relayed by the server:

```json
{ "type": "message", "from": "3790E593", "data": "{ ...payload... }" }
```

## The layers, in order

<Accordion>
  <AccordionItem title="Session layer (extension/src/session.ts)">
    Holds the active session — server-assigned room ID, role (`host` or
    `guest`), and creation time. Pure state, no I/O.
  </AccordionItem>
  <AccordionItem title="Connection layer (extension/src/connection.ts)">
    Creates rooms over HTTP, then owns one WebSocket per session with a 3s
    auto-reconnect loop. Close code `1008` (bad room) is treated as fatal so a
    typo'd ID never spins a reconnect storm.
  </AccordionItem>
  <AccordionItem title="Presence layer (extension/src/presence.ts)">
    Broadcasts cursor/selection offsets every 150ms and renders each peer's
    ranges as a colored decoration — the color is hashed from the peer's
    client ID.
  </AccordionItem>
  <AccordionItem title="Sync layer (extension/src/sync.ts)">
    A <Tooltip tip="Conflict-free Replicated Data Type — a structure that merges concurrent edits without coordination." headline="CRDT" cta="See text sync" href="/features/text-sync">CRDT</Tooltip>-backed
    document mirror per file, using Yjs. Hosts broadcast initial state; every
    local edit becomes a binary delta relayed to peers.
  </AccordionItem>
  <AccordionItem title="Relay (server/src/server.ts)">
    Deliberately dumb: validates JSON, fans frames out to the other room
    members, deletes empty rooms. No document storage ever touches disk.
  </AccordionItem>
</Accordion>

:::note
The server never persists content. If the last peer leaves, the room — and
everything in it — is gone. That's a feature.
:::
